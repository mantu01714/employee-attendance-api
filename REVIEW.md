# REVIEW.md

List every defect found in the starter `app/main.py`. For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How it was fixed |
|---|---|---|---|---|
| 1 | `health()` (line 73–74) | Never pings MongoDB. Returns 200 even when the database is down. Spec: "Returns 200 only if MongoDB answers a ping, otherwise 503." | Stop MongoDB, call `GET /health` → still returns 200 instead of 503. | Added `db.command("ping")` inside a try/except; raises `HTTPException(503)` on failure. |
| 2 | `create_employee()` (line 79) | Check-then-insert race condition for `emp_code` uniqueness. Two simultaneous creates with the same `emp_code` can both pass the `find_one` check and both insert. Spec: "concurrent duplicate creates must yield exactly one 201 and the rest 409 — do not rely on check-then-insert." | Send two simultaneous `POST /employees` with identical `emp_code` → both return 201. | Created a unique index on `employees.emp_code` at startup; replaced the `find_one` check with a `try/except DuplicateKeyError` around `insert_one`. |
| 3 | `create_employee()` (line 82) | `datetime.now()` produces a naive (no-timezone) datetime. The grader's seeded data uses UTC-aware datetimes. PyMongo with `tz_aware=True` returns aware datetimes, so mixing naive and aware datetimes causes comparison errors. | Reading a created employee back and comparing `created_at` with a seeded record would fail or behave unexpectedly. | Changed to `datetime.now(tz=timezone.utc)`. |
| 4 | `create_employee()` response (line 84–85) | Returns `created_at` as a Python `datetime` object (FastAPI serialises it as an ISO string), but the spec requires epoch **milliseconds** (an integer). | `GET /employees` would return a string for `created_at` instead of an integer. | Added `employee_to_api()` helper that converts `created_at` to `dt_to_ms()`. |
| 5 | `create_employee()` — missing validation | No check that `shift_start != shift_end`. Spec: "`shift_start` must differ from `shift_end`." | `POST /employees` with `shift_start` == `shift_end` returns 201 instead of 422. | Added `@model_validator` in `EmployeeCreate` that raises `ValueError` when they are equal. |
| 6 | `list_employees()` (line 93) | `skip = page * page_size` is wrong. For page 1 this skips the first 20 records. The correct formula is `(page - 1) * page_size`. | `GET /employees?page=1` returns the second page of results. | Changed to `(page - 1) * page_size`. |
| 7 | `list_employees()` (line 94) | `count_documents({})` ignores the `department` filter, so `total` is the count of all employees instead of the filtered count. R10: "`total` always reflects the applied filters." | `GET /employees?department=Sales` returns `total` equal to the full collection size, not 2. | Changed to `count_documents(q)` where `q` already holds the department filter. |
| 8 | `list_employees()` — no sort | No `.sort("emp_code", 1)`. Spec: "Sorted by `emp_code` ascending." | Order of results is indeterminate; fails determinism check. | Added `.sort("emp_code", ASCENDING)` to the cursor. |
| 9 | `list_employees()` — no pagination validation | `page` and `page_size` have no bounds validation. Spec R10: page_size max 100. | `?page_size=9999` is accepted without error. | Used `Query(default=20, ge=1, le=100)` and `Query(default=1, ge=1)` in the function signature. |
| 10 | `punch_in()` (line 102) | `datetime.fromtimestamp(...)` without a timezone produces a naive local-time datetime. If the server is not in IST, the punch_in instant stored in MongoDB is wrong. | On a UTC server, a punch at 00:30 UTC (06:00 IST) stores as local midnight instead of 00:30 UTC. | Changed to `ms_to_dt()` which uses `datetime.fromtimestamp(..., tz=timezone.utc)`. |
| 11 | `punch_in()` (line 103) | `ts.date().isoformat()` derives the attendance date from the UTC date, not the IST date. R1 requires the IST calendar date. | A punch at 23:50 UTC (05:20 IST next day) creates a record for the UTC date, not the IST date. | Implemented `attendance_date()` that converts to IST first, and handles overnight shift logic. |
| 12 | `punch_in()` (line 104) | Check-then-insert race condition (same pattern as employee creation). Two simultaneous punch-ins for the same employee and date can both succeed. | Two concurrent requests for the same employee on the same date → two records, violating the unique constraint. | Unique compound index on `(emp_code, date)` is created at startup; `insert_one` is wrapped in `try/except DuplicateKeyError`. |
| 13 | `punch_in()` — no 404 | `db.employees.find_one({"emp_code": ...})` result is never checked for `None`. If the employee does not exist, the next line `emp["shift_start"]` raises a `TypeError` → 500. | `POST /attendance/punch-in` with an unknown `emp_code` → 500 instead of 404. | Added `if emp is None: raise HTTPException(404, ...)` immediately after the query. |
| 14 | `punch_in()` — status not validated | `status: str = "PRESENT"` accepts any string, including `"ABSENT"` and `"LEAVE"`. Spec: only `PRESENT`, `WFH`, `ON_DUTY` are valid here. | `{"emp_code": "EMP0001", "status": "ABSENT"}` → 201 instead of 422. | Added a `@field_validator("status")` in `PunchInRequest` that checks membership in `PRESENCE_STATUSES`. |
| 15 | `punch_in()` response (line 119) | Returns `doc["id"] = str(res.inserted_id)` — an `id` field that is not in the `AttendanceRecord` schema. Also `punch_in` is stored as a `datetime`, returned as-is (not epoch ms). | Response fails the spec schema; `punch_in` is an ISO string not an integer. | Removed `id` field; added `record_to_api()` helper that converts datetimes to epoch ms. |
| 16 | `list_attendance()` (lines 144–146) | Loads the **entire** filtered collection into a Python list (`list(db.attendance_logs.find(q))`), then sorts in Python. Spec: "must stay fast on ~100,000 records; do not load the collection into memory." | On a 100k-record collection: out-of-memory or very slow response. | Removed in-memory load; replaced with `.sort(...).skip(...).limit(...)` on the cursor, all executed on MongoDB. |
| 17 | `list_attendance()` (line 149) | Returns an `id` field (from converting `_id`) not in the schema. `punch_in`/`punch_out` are raw `datetime` objects, not epoch ms. | Response schema mismatch; `punch_in` value is an ISO string. | Applied `record_to_api()` to each document. |
| 18 | `compute_late_minutes()` (line 36–37) | Uses `int(diff / 60)` which truncates toward zero (same as floor for positive numbers — actually OK), but the `replace(hour=h, minute=m)` on `punch_in` inherits the punch_in's timezone info (which was naive in the old code). Also does not handle overnight shifts where the attendance date is a day before the punch_in date. | Late minutes for an overnight shift employee whose punch_in is past midnight IST would be calculated against the wrong shift_start date. | Rewrote to `compute_late_minutes(punch_in, shift_start, date_str)` that builds shift_start as an IST-aware datetime on the attendance date. |
| 19 | `compute_work_hours()` | Uses Python's `round()` which uses banker's rounding. Spec R4: "rounded to 2 decimals half-up (not banker's rounding)." | `round(2.125, 2)` → 2.12 (banker's) instead of 2.13 (half-up). | Replaced with `half_up()` using `math.floor(value * 100 + 0.5) / 100`. |
| 20 | `compute_overtime()` (line 46) | For overnight shifts, `shift_end` is on the next calendar day. The function uses `date_str` for both shift start and end, so overnight shift_end is placed on the wrong day, making overtime always 0 or wildly negative. | `EMP0005` (22:00–06:00 shift) punching out at 06:40 IST would show 0 overtime instead of 40. | Rewrote to detect overnight shifts and place `shift_end` on `date_str + 1 day` when overnight. |
| 21 | No indexes at startup | No indexes are created anywhere. Spec: "Create all indexes at startup, idempotently." No unique index → race conditions; no query index → COLLSCAN on the grader's 100k dataset. | Concurrent duplicate creates/punch-ins both succeed; `/admin/explain` shows COLLSCAN instead of IXSCAN. | Created three indexes at module load time: unique on `employees.emp_code`; unique compound on `attendance_logs(emp_code, date)`; compound on `attendance_logs(date DESC, emp_code ASC)`. |
| 22 | Missing endpoints (lines 153–162) | Seven endpoints listed as TODO are not implemented: `POST /attendance/punch-out`, `PATCH /attendance/{emp_code}/{date}`, and all four analytics + one admin endpoint. | Any call to these paths returns 404 (FastAPI default) or 405. | Implemented all seven endpoints. |

## Items reviewed and decided are NOT defects

- The `IST = timezone(timedelta(hours=5, minutes=30))` constant is correct.
- `load_dotenv()` before the client setup is correct — environment variables override `.env` values.
- The use of `body.model_dump()` in `create_employee` is correct Pydantic v2 syntax.
- The `Optional[int]` type for `punched_at` (allowing omission) is correct per the spec.
